## 문제와 해결
- 증상: 움직임 줄이기 설정이면 타이머 "시간 종료" 숫자가 아주 빠르게 번쩍임 (코드 점검)
  - 원인: 전역 규칙이 `animation-duration: 1ms`만 주고 `infinite` 반복은 그대로 → 1ms마다 깜박임. 줄이려던 사용자에게 오히려 위험(WCAG 2.3.1)
  - 조치: `animation-iteration-count: 1 !important` 추가, E2E로 확인
- 증상: 8팀 점수판에서 버튼 줄바꿈을 허용하자 숫자와 버튼이 겹침 (스크린샷) → `min-content` 행 높이로 바꾸자 넓은 위젯도 항상 세로로 쌓임
  - 원인: 줄바꿈 가능한 flex의 min-content는 "항목마다 한 줄"
  - 조치: 줄바꿈 대신 열 수를 줄임(`auto-fill, minmax(max(3.75rem, 100%/cols))`), 행은 `minmax(min-content, 1fr)` + 모자라면 스크롤, 팀 5개 이상은 낮은 위젯에서 이름 숨김·버튼 36px
- 증상: 보드 메뉴의 이름 변경 대화상자를 Esc로 닫으면 포커스가 `<body>`로
  - 원인: 연 요소(메뉴 버튼)가 닫힌 `<details>` 안이라 포커스를 받을 수 없는데, `getClientRects()`는 상자를 돌려줘 "보인다"고 판단
  - 조치: 후보(연 요소 → 보드 메뉴 버튼 → 캔버스)에 차례로 `focus()` 후 `document.activeElement`로 실제 이동 확인
- 증상: 강제 색상 모드에서 위젯 경계가 1px 그대로
  - 원인: `base.css`가 `app.css`보다 먼저 로드 → 같은 명시도의 `.widget` 규칙에 짐
  - 조치: 강제 색상 블록 선택자에 `:root ` 접두어 (30개)
- 증상: 위젯 모양을 넣어 길어진 보드 메뉴의 아래쪽이 독 뒤로 가려짐 (기존 문제가 드러남)
  - 원인: 팝오버 `z-index`는 툴바(z 100)의 쌓임 맥락 안이라 같은 z의 독(나중 DOM)보다 아래
  - 조치: `.toolbar:has(details[open])`의 z-index를 팝오버 수준으로
- E2E: 하네스 `key()`는 `rawKeyDown`만 보내 Enter로 버튼이 눌리지 않음 → m6에 char 이벤트가 있는 `enter()`
- Bash heredoc 안 `'\r'`·`\|`가 깨지는 함정이 2번 재발 (CLAUDE.md에 있음) → Edit 도구로 수정
- 전체 E2E를 연달아 돌릴 때 m1·m3·m5가 1번 결과 줄 없이 끝남. 출력 필터 때문에 오류 내용을 못 남김 → 로그를 파일로 남기며 다시 돌리자 6개 모두 통과, 단독 실행도 통과. 원인 미확인 — 파일을 막 바꾼 직후 첫 로드가 느려 `ready()` 8초를 넘긴 경우로 추정(스크린샷 스크립트에서도 sw-stamp 직후 첫 실행만 "독 없음" 3회). 재발하면 로그 확인

## 결정 사항 (계획에 없던 선택 → 권장안)
- 점검 상태에 "내용을 채운 위젯"(명단·모둠·8팀·글자 색·신호등 각 색)을 추가 — 빈 위젯만으로는 색 결함이 안 보였음
- 팀 색을 **면용 `--team-*`(3:1) / 글자용 `--team-*-text`(4.5:1)** 두 벌로 분리, 신호등 문구도 같은 토큰 사용 (색 하나로 두 기준을 다 맞추면 면이 너무 어두워짐)
- 라이트 테마 면 색 조정: 주황 `#ce7800`, 청록 `#119e8e`, 노랑 `#b08700` / 다크 보라 `#975ccb` (3:1 미달이었음)
- 툴바 2개를 이름 있는 `<section>`(랜드마크)으로, 숨긴 `<h1>`은 보드 도구 영역 안으로
- 낭독기 알림은 위젯마다 `aria-live`를 다는 대신 **결과 전용 숨김 영역**(`liveRegion()`)에 사용자 조작 직후 1번만 — 연출·다시 그리기·페이지 로드에서 읽히지 않게
- 위젯 프레임 조작 안내는 프레임마다 문구를 넣지 않고 숨김 문구 1개를 `aria-describedby`로 공유
- 알림 가림 판단은 위젯이면 **제목 막대**(위 44px) 기준 — 이동·삭제 버튼이 가려지지 않는 것이 중요
- 점수판 팀 5개 이상: 버튼 높이 36px (터치 권장 44px보다 작지만 WCAG 2.5.8의 24px 이상, 8팀이 최소 크기 위젯에 들어가게)
- 위젯 모양 "테두리"는 배경을 투명하게 하지 않고 바탕색 유지 + 진한 테두리·그림자 없음 (투명하면 사진 배경 위 글자 대비를 보장할 수 없음)
- 위젯 모양을 기본값으로 되돌리면 `widgetStyle` 필드를 지움 (저장 데이터를 이전과 같게)
- 강조색은 제목 막대 배경이 아니라 **위쪽 띠 + 제목 글자색** (배경을 칠하면 흰 글자 대비가 4.5:1 미달인 색이 있음)
- 활동 상징을 고르면 직접 쓴 문구는 지움 (예전 상징의 문구가 남아 헷갈리지 않게), 고르기 격자 열 수는 위젯 폭에 따라 바뀌고 ↑↓는 실제 열 수로 계산
- 활동 상징 색 = 테마 강조색 (`--color-accent`, 바탕 대비 3:1 테스트됨)
- 템플릿은 바꾸지 않음 (계획대로 — 기존 사용자 혼란 방지)
