## 문제와 해결
- 증상: 위젯 6개 추가 후 로컬 모바일 Lighthouse 93 → **86** (LCP 3.0 → 3.8s)
  - 원인: LCP 요소가 빈 보드 안내 문구인데, 문구가 **모든 모듈(81개) 로드 후** 번역됨 (Render Delay 88%)
  - 조치: `main.js`는 i18n·로케일·번역 함수만 정적 import → 문구·테마를 먼저 그리고 `app.js`를 동적 import. 저장된 보드가 있으면 안내 문구를 앱이 판단할 때까지 숨김(깜박임 방지) → 93 회복
  - 부작용: E2E가 고정 1200ms 대기 후 클릭하다 가끔 실패 → 하네스에 `ready()` 추가, m1~m4 적용
- 증상: 주사위 점이 점선처럼 아주 작게 보임 (스크린샷)
  - 원인: `aspect-ratio` 높이 + 퍼센트 `gap`/`padding` → 격자 행 높이가 0에 가깝게 계산
  - 조치: 면 크기를 `--size`로 명시(width·height), 간격·여백도 `--size` 배수
- 증상: 가져오기 직후 첫 보드 배경 이미지가 안 보임
  - 원인: 캔버스가 "이미 적용한 이미지 ID"를 기억 → 이미지가 없던 같은 ID를 다시 적용하지 않음
  - 조치: 기억 키를 보드 ID + 이미지 ID로
- 증상: QR SVG의 흰 바탕이 정사각형이 아님 (336×290)
  - 조치: SVG를 `container-type: size` 상자에 넣고 `min(100cqw, 100cqh)`로 정사각형
- Bash에서 `node -e "..."` 안의 백틱 템플릿 문자열이 명령 치환으로 깨짐(2회), heredoc의 `\\`가 `\`로 바뀜 → Write 도구로 만든 스크립트 파일로 수정 (CLAUDE.md 함정에 추가)
- 첫 E2E 실행에서 m4 독 검사가 "독 없음"으로 1회 실패 → 위 `ready()`로 해결

## 결정 사항 (계획에 없던 선택 → 권장안)
- **QR 라이브러리 버전**: Nayuki 최신 v1.8.0은 TypeScript(namespace)라 컴파일 필요 → 빌드 금지 원칙상 **마지막 순수 JS판 v1.4.0**을 원본 그대로 사용, 일반 스크립트라 동적 import 대신 `<script>` 지연 로드, 해시 테스트로 고정 (ADR-0006)
- QR 자동 판독 검증: Windows Edge에 `BarcodeDetector`가 없어 생략 → 라이브러리 알려진 값·파인더 패턴·path 일치 단위 테스트 + 실기기 스캔은 QA 9절
- 작은 이미지(2048px·2MB 이하)는 **원본 그대로** 저장 → GIF 움직임 유지, 화질 손실 없음
- object URL은 위젯 `destroy()`에서 해제하지 않고 **세션 캐시로 공유**(같은 이미지를 배경·위젯이 함께 씀), GC로 지운 이미지만 해제
- 이미지 GC는 저장 데이터를 문제없이 읽었을 때만 (복구·임시 저장소면 남은 참조를 모르므로 건너뜀)
- 가져오기 이미지 하나 최대 10MB, 전체 파일 30MB
- 주사위 개수를 바꾸면 이전 결과를 지움 (합계 혼동 방지)
- 카운트다운 영어 일 표시는 `{n}d` (복수형 처리 없이 "1 days" 방지)
- 소음: 감도별 바닥 -45/-55/-65dBFS, 천장 -10dBFS, 경고 기준 5~95 (5단위)
- 그리기 도구(색·굵기·지우개)는 저장하지 않음 (위젯을 다시 열면 기본 펜)
- 독 순서: 계획안 그대로 (시간 → 무작위 → 진행 → 표시)
