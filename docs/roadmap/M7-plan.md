# M7 실행 계획: 생태계 (v0.5.0 → v1.0.0)

| status | version | updated | owner |
|---|---|---|---|
| ready | 1.0 | 2026-11-09 | @owner |

> "m7 진행해줘"라고 하면 **추가 확인 없이** 1절부터 이 문서 순서대로 바로 진행한다.
> 범위: 추가 언어(ja·es)와 번역 기반, 위젯·번역 기여 가이드와 위젯 템플릿 생성기, 스키마·위젯 인터페이스 안정화 선언. 기간: 약 2주. 결과 버전: **v0.5.0**(언어) → **v1.0.0**(안정화).
> 0절 결정은 권장안으로 정했다 (사용자는 권장안 위임을 선호). 바꾸려면 사용자가 먼저 말한다.
> 중간 출시(v0.5.0)와 최종 출시(v1.0.0)의 커밋·병합·배포·태그는 각각 **사용자 요청 시에만**.

## 2. 공통 규칙 (M7 전체)

- 문구는 **4개 언어 모두** 추가 (빠지면 i18n-check·단위 테스트 실패). 영어가 기준(fallback)
- 번역 원칙: 교실에서 큰 화면으로 읽는 짧은 말, 존댓말 수준 통일(ja: です・ます체, es: 학생에게 보이는 문구는 vosotros 대신 지역 중립적인 ustedes/명령형 최소화 — 3-3 용어집), 기능 이름은 독 라벨 폭(약 9자) 고려
- 레이아웃: 새 언어마다 툴바·독·메뉴·대화상자·위젯 기본 크기에서 **글자 넘침 0**(E2E 검사), 원거리 글자 18px 이상 유지
- 계약 감사(3-5)에서 **기존 데이터·위젯 코드를 깨는 변경 금지** (D6)
- 앱 파일 변경 후 `tools/sw-stamp.mjs`, 상태 변경은 `actions.perform`, 결과 알림은 `liveRegion()` (CLAUDE.md 함정)

## 3. 작업 순서

번역 기반(도구·복수형) → 언어 추가 → v0.5.0 → 계약 확정 → 기여 진입로 → v1.0.0.

### 3-0. 기반 (0.5일)
- `tools/i18n-check.mjs`: 언어별 키 수·누락·여분·자리표시자 불일치·빈 값·영어와 동일 값 표를 출력, 문제 있으면 종료 코드 1. `ci.yml`에 단계 추가
- E2E 도우미 `overflow(selectorList)`: 요소의 `scrollWidth > clientWidth`(줄임표 처리된 요소는 제외 목록) — 독 라벨·메뉴 버튼·대화상자 버튼·위젯 제목·설정 패널 라벨
- 글꼴: `--font-sans`에 일본어(`'Hiragino Sans'`, `'Yu Gothic UI'`, `'Meiryo'`) 추가 — `lang="ja"`에서 중국어 자형으로 보이지 않게

### 3-1. 복수형 (1일)
- `core/i18n.js`: 값이 객체이고 `params.n`이 숫자면 `new Intl.PluralRules(locale).select(n)` 범주 → 없으면 `other`. `flattenMessages`는 복수형 객체를 한 항목으로 취급
- 영어 정리: `Last backup: {n} day(s) ago`, `{count} widget(s)`, `Imported {n} board(s).`, `{n} widgets`, `{n} names` 등 → `{ one, other }`
- 한국어는 그대로(문자열 = `other`), i18n-check가 언어별 필요한 범주(`Intl.PluralRules(locale).resolvedOptions().pluralCategories`)를 확인
- 테스트: 범주 선택(en 1/2, es 1/2, ja 1·2 → other), 자리표시자 치환, 폴백, 객체가 아닌 값과 섞여도 동작

### 3-2. 일본어 ja (1.5일)
- `src/locales/ja.js` (현재 356개 키 전부), `localeNames.ja = '日本語'`
- 용어집(devlog 결정): 위젯 이름(タイマー·ストップウォッチ·ランダム指名·グループ分け·得点板·信号·活動シンボル …), 보드=ボード, 템플릿 문구(今日の目標·休み時間 …)
- 날짜·시각은 기존 `Intl` 그대로 (`11月9日(月)` 형식 확인), 카운트다운 일 표시
- 스크린샷: 위젯 15종·템플릿 대화상자·공유·단축키·영어와 나란히 넘침 검사

### 3-3. 스페인어 es (1.5일)
- `src/locales/es.js`, `localeNames.es = 'Español'`, 지역 중립 스페인어(es-419·es-ES 모두 `es`로 감지 — `detectLocale` 테스트 추가)
- 복수형 `{ one, other }`, 영어보다 평균 20~30% 긴 문구 → 독 라벨·메뉴 버튼·점수판 팀 이름(`Equipo 1`) 넘침 확인, 필요하면 짧은 대안어
- 학생에게 보이는 문구(신호등 기본 문구·활동 상징 이름·템플릿 문구)는 짧은 명령형/명사형으로 통일

### 3-4. 언어 마무리·v0.5.0 (1일)
- 언어 메뉴: 자기 언어 이름, 순서 = English · Español · 日本語 · 한국어 (코드 순), 메뉴 아래 "번역 개선 제안" 링크(GitHub Issue 템플릿 `translation.md`)
- `index.html`·`main.js` 첫 화면: 저장된 언어/감지 언어로 4개 모두 깜박임 없이 (기존 earlyPaint 경로)
- 각 언어로 a11y 점검(axe `html-lang-valid` 등)과 템플릿 6종 생성
- E2E `tools/e2e/m7.mjs` 1부(언어) 통과 → 문서(PRD·TRD i18n 절·README·CHANGELOG `[0.5.0]`·릴리스 노트 `v0.5.0.md`·devlog) → **사용자 승인 후 v0.5.0 출시**

### 3-5. 위젯 계약 감사 (1일)
- TRD 2.2 계약과 실제 15종 구현을 대조해 v1 전에 정리할 것을 목록화 → **추가형만** 반영:
  - `ctx.locale` 추가 (지금은 시계·카운트다운이 `document.documentElement.lang`을 직접 읽음)
  - 위젯이 써도 되는 공용 모듈을 **공개 범위로 명시**: `widgets/shared/ui.js`(설정 패널·입력 요소·`liveRegion`), `core/utils/random.js`, `core/contrast.js` 토큰 규칙 / 나머지 내부 모듈은 비공개
  - 계약 검사 강화: `validateWidgetDefinition`에 `titleKey`가 모든 언어에 있는지(테스트 쪽), `styleUrl` 같은 출처
- ADR-0011 "v1 공개 계약" (D6): 범위·SemVer·폐기(deprecation) 절차(최소 1 minor 동안 경고 후 major에서 제거)·저장 데이터 하위 호환 약속
- data-schema·TRD 2.2를 "v1 계약" 표시로 갱신
