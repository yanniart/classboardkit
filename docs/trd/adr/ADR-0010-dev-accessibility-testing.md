# ADR-0010: 접근성 자동 점검은 개발 전용 axe-core + 접근성 트리 검사

- 상태: Accepted
- 날짜: 2026-11-09

## 배경
- NFR-005: WCAG 2.1 AA 지향, 모든 조작 키보드 가능. M6에서 점검·개선한다.
- Lighthouse 접근성 점수(100)는 **첫 화면**만 본다. 위젯 15종·설정 패널·대화상자·테마·꾸미기 조합은 확인하지 못한다.
- 런타임 외부 라이브러리 0 원칙(NFR-009)과 빌드 없음(ADR-0001)은 유지해야 한다.
- 이 PC에는 스크린리더 자동화 수단이 없다.

## 선택지
1. **axe-core를 개발 중에만 받아 E2E에서 페이지에 주입** + CDP 접근성 트리로 이름·역할 검사
2. 직접 작성한 검사만 (대비·이름·역할)
3. Lighthouse만

## 결정
**1.** (M6 결정 D1·D3·D4)
- `axe-core` 4.10.3을 npm 레지스트리 tarball에서 받아 `.tools/axe/axe.min.js`에 둔다(git 제외, 배포물 아님). 받을 때 레지스트리 integrity(SHA-512)를 확인한다. 라이선스 MPL-2.0 — 수정·배포하지 않으므로 의무 없음
- `tools/e2e/a11y.mjs`: `axe()`(WCAG 2.0·2.1 A/AA + 2.2 AA + best-practice 태그), `axTree()`(이름 없는 상호작용 요소), `axNode()`
- `tools/e2e/a11y-states.mjs`: 점검 상태 40개(빈 보드, 위젯 15종, 내용이 채워진 위젯 × 테마 3, 신호등·글자 색 전부, 설정 패널 전부, 메뉴·대화상자·알림, 위젯 모양 조합 × 라이트·다크, 768px, 영어)
- `tools/e2e/a11y-audit.mjs`(진단 표) · `tools/e2e/m6.mjs`(합격 기준: critical·serious 0, 이름 없는 요소 0)
- axe 파일이 없으면 접근성 트리 검사만 하고 경고 (다른 환경에서도 E2E가 깨지지 않게)
- 색 대비는 따로 **단위 테스트**(`tests/contrast.test.js`)로 토큰을 직접 계산 — axe는 겹친 요소·반투명 배경에서 판단을 보류하는 경우가 있어서
- 스크린리더 실측(NVDA·VoiceOver)은 QA 11절로 사람이 확인

## 결과
- 장점: 업계 표준 규칙 세트로 여러 화면 상태를 반복 점검, 배포물·런타임 의존성 변화 없음, 회귀 방지
- 단점: 개발 환경 준비 단계가 하나 늘어남(포터블 Node와 같은 방식), 자동 점검은 실제 낭독 품질을 보장하지 않음
- 보완: CLAUDE.md에 받는 명령 기록, live region 정책(TRD 2.2.4)을 E2E로 확인, QA 11절 실측 요청
