# ADR-0008: 공유 링크는 URL 조각(#) + 브라우저 내장 압축

- 상태: Accepted
- 날짜: 2026-11-09

## 배경
- F-012: 교사가 만든 보드를 동료에게 보내고 싶다. 서버·계정 없음(ADR-0002), 런타임 의존성 0 원칙은 유지해야 한다.
- 이미 파일 내보내기/가져오기(F-005)가 있지만 파일 전달은 번거롭다. 링크 하나로 열 수 있어야 한다.
- 보드에는 학생 이름(랜덤 뽑기·모둠 편성 명단)이 들어갈 수 있다.

## 선택지
1. **URL 조각 `#share=` + `CompressionStream('deflate-raw')` + base64url**
2. 쿼리 문자열 `?share=` — 서버(GitHub Pages) 접근 로그에 남음
3. 압축 없는 JSON — 링크가 3~5배 길어짐
4. 직접 구현한 압축(LZ 계열) 또는 라이브러리 — 코드·검증 부담, 의존성

## 결정
**1. 조각 + 내장 압축** (M5 계획 D3~D6)
- 형식: `<앱 주소>#share=1.<base64url(deflate-raw(JSON))>` — `1.`은 공유 형식 버전
- JSON 내용은 **내보내기 형식 그대로**(`createExport([board])`, data-schema §1) → 받는 쪽은 기존 `parseImport` 검증·새 ID 발급 경로를 재사용. 저장 스키마는 바뀌지 않는다
- 공유 범위: 현재 보드 1개. **이미지는 항상 제외**(이미지 위젯 `assetId: null`, 이미지 배경 → 기본). **"명단 제외" 기본 켬**: 랜덤 뽑기 `items·picked·history`, 모둠 편성 `items·result` 비움
- 길이: 링크 전체 **32,000자 초과면 공유 대신 파일 내보내기 안내**, **2,000자 이하면 QR 코드도 표시**(벤더링한 Nayuki 라이브러리, ADR-0006)
- 여는 쪽: **확인 대화상자 후** 새 보드로 추가 (링크를 여는 것만으로 데이터가 바뀌지 않음), 처리 후 `history.replaceState`로 `#share` 제거
- 방어: 조각 길이 상한 확인 → base64url 문자 집합 확인 → **압축 해제 출력 1MB 상한**(스트림으로 읽다가 넘으면 중단, 압축 폭탄) → `parseImport`
- `CompressionStream` 미지원 브라우저: "공유 링크" 메뉴를 숨기고, 링크를 받은 경우 안내 문구
- 구현: 순수 로직 `src/core/share.js`(압축 함수 주입 → Node 테스트는 `node:zlib`), 브라우저 부분 `src/ui/share-dialog.js`

## 결과
- 장점: 조각은 HTTP 요청에 포함되지 않아 서버 로그·리퍼러에 남지 않음, 의존성 0, 오프라인(SW 캐시)에서도 열림, 가져오기 검증 재사용
- 단점: 링크가 길다(위젯 몇 개면 수백 자, 그림 위젯이 크면 수만 자). 메신저가 긴 링크를 자를 수 있음. 링크를 가진 사람은 누구나 내용을 볼 수 있음(암호화 없음)
- 보완: 32,000자 상한과 파일 내보내기 안내, 잘린 링크 전용 오류 문구, 대화상자에 "링크를 받은 사람은 이 보드 내용을 볼 수 있어요" 안내, 명단 제외 기본값
- 브라우저 요구: `CompressionStream('deflate-raw')` — Chrome 103+, Safari 16.4+, Firefox 113+ (NFR-001 범위)
