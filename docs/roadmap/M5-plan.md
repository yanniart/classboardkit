## 2. 공통 규칙 (M5 전체)

- 순수 로직은 `src/core/`(history·share·templates 검증) → Node 테스트, DOM은 `src/ui/`
- 새 문구는 ko/en 둘 다, 앱 파일 변경 후 `tools/sw-stamp.mjs`
- Bash `node -e` 안에 백틱 금지·백슬래시 든 스크립트는 Write 도구로 (CLAUDE.md 함정)
- E2E는 이동·새로고침 뒤 `b.ready()`
- 저장 스키마(`schemaVersion` 1)는 바꾸지 않는다 — 실행 취소 기록은 저장하지 않고, 공유 링크는 내보내기 형식을 재사용

## 3. 작업 순서

의존성이 적고 다른 기능이 기대는 것(실행 취소) → 데이터만 추가하면 되는 것(템플릿) → 인코딩·개인정보가 걸린 것(공유) 순서.

### 3-0. 기반 (0.5일)
- 아이콘 추가: `redo`, `share`, `link`, `template`(레이아웃 격자) — `undo`는 M4에 있음
- ADR-0008 "공유 링크는 URL 조각 + 내장 압축" 작성 (D3~D6), ADR-0009 "실행 취소는 역연산 기록" 작성 (D1·D2)

### 3-1. 실행 취소 코어 F-014 (1.5일)
- `core/history.js` (순수):
  - `createHistory({ limit = 50 })` → `{ record(entry), undo(state), redo(state), canUndo, canRedo, clear(), peek() }`
  - entry = `{ label: i18n 키, undo: (state) => state, redo: (state) => state }` — 함수는 대상 ID로 동작(배열 위치에 기대지 않음)
  - 새 작업을 기록하면 redo 스택 비움, 상한 넘으면 오래된 것부터 버림
  - 같은 위젯의 연속 키보드 이동(화살표, 1초 이내)은 한 항목으로 **합치기**(`mergeKey`)
- `board-ops.js`에 역연산 헬퍼: `restoreWidget(state, boardId, widget, index)`(삭제 취소: 원래 z·위치·state 그대로), `restoreBoard(state, board, index)`(보드 삭제 취소 → 원래 순서·활성 보드)
- 대상 보드가 없어졌으면 해당 항목은 건너뛰고(no-op) 다음 기록으로 넘어감 — 예외 없이
- 테스트: 각 작업의 기록 → undo → redo 왕복이 원래 상태와 같음, 중간에 다른 위젯 state가 바뀌어도 그 변경은 유지, 상한·redo 비우기·합치기, 없어진 대상 건너뜀

### 3-2. 실행 취소 UI (1일)
- 기록 지점: 캔버스(드래그 끝·키보드 이동/크기·삭제 버튼·Delete 키), 독(추가), 보드 메뉴(배경·이름 변경·삭제), 템플릿·공유로 보드 추가
  - 한 곳(`ui/actions.js` 또는 `commit(label, forward)` 헬퍼)에서 "적용 + 기록"을 함께 해 누락 방지
- 조작: **Ctrl+Z / ⌘Z**, **Ctrl+Shift+Z / Ctrl+Y / ⌘⇧Z** (입력 요소·contenteditable·설정 패널 안에서는 브라우저 기본 동작 유지), 툴바 실행 취소·다시 실행 버튼(태블릿용, 불가능하면 비활성)
- 위젯·보드 삭제 후 정보 알림 "삭제했어요 — **실행 취소**" (기존 `notify` action, 6초)
- 보드 전환해도 기록 유지, 실행 취소가 다른 보드의 작업이면 그 보드로 전환 후 적용
- 언어 변경·새로고침 시 기록은 사라짐 (세션 한정, 문서화)
- 이미지 위젯 삭제 → 실행 취소: 이미지 GC는 시작 시 10분 유예라 같은 세션에서는 이미지 유지 (E2E로 확인)

### 3-3. 템플릿 F-013 (2일)
- `src/templates/index.js`: `{ id, nameKey, descKey, background, widgets: [{ type, rect: [x, y, w, h], state?: (t) => state }] }` — state가 없으면 위젯 `createState()`
- 6종 (모두 겹침 없이 배치, 위젯 3~5개):
  1. **수업 시작**: 시계 · 텍스트("오늘의 목표") · 타이머 5분 · 신호등
  2. **모둠 활동**: 모둠 편성 · 타이머 15분 · 소음 측정기 · 신호등
  3. **발표 순서**: 랜덤 뽑기(중복 제외) · 스톱워치 · 점수판
  4. **퀴즈·게임**: 점수판 4팀 · 주사위 2개 · 타이머 30초
  5. **조용한 활동/시험**: 시계(초 표시) · 카운트다운(오늘 끝 시각 대신 기본값) · 텍스트("휴대폰은 가방에") · 소음 측정기(얼굴)
  6. **쉬는 시간**: 타이머 10분(원형) · 텍스트 · QR 코드(빈 내용 → 입력 안내) · 그리기
- UI: 보드 메뉴 "새 보드" 옆에 **"템플릿에서"** → 대화상자(카드 6개: 미니 배치도 + 이름 + 설명), 고르면 새 보드 생성·전환 (실행 취소 가능)
  - 미니 배치도는 rect로 그린 회색 사각형 + 위젯 아이콘 (이미지 없음)
- 테스트: 모든 템플릿이 `validateBoard` 통과, 등록된 위젯 타입만 사용, rect가 0~1·서로 겹치지 않음·독 영역(아래 12%) 피함, ko/en 키 존재, 생성 결과 ID 고유
- 빈 보드 안내에 "템플릿으로 시작하기" 링크 추가 (첫 방문 G1: 30초 안에 첫 위젯)

### 3-4. 공유 링크 만들기 F-012 (2일)
- `core/share.js` (순수 + 주입형 압축):
  - `buildSharePayload(board, { excludeNames })` → 내보내기 객체(`createExport([board])`)에서 이미지 제거(`assetId: null`, 이미지 배경 → 기본), 명단 제외 시 randomizer `items·picked·history`, groups `items·result` 비움
  - `encodeShare(obj, compress)` → `'1.' + base64url(deflate-raw(JSON))`, `decodeShare(str, decompress)` → 객체 (접두어·문자 집합·길이 확인)
  - base64url 변환, 길이 판정(`MAX_SHARE_LENGTH = 32000`, `QR_SHARE_LENGTH = 2000`)
  - Node 테스트는 `node:zlib`의 `deflateRawSync`로 같은 인터페이스 주입 (브라우저는 `CompressionStream`)
- UI: 보드 메뉴 "공유 링크" → 대화상자
  - 체크박스 "명단 제외(학생 이름 보호)" 기본 켬, "이미지는 공유 링크에 포함되지 않아요" 안내(이미지가 있을 때만)
  - 링크 미리보기(읽기 전용 입력) + **복사**(`navigator.clipboard.writeText`, 실패 시 입력 선택) + **공유…**(`navigator.share`가 있을 때만, 태블릿)
  - 2,000자 이하면 QR 표시 (M4 벤더링 라이브러리 지연 로드 재사용), 32,000자 초과면 "보드가 커서 링크로 공유할 수 없어요 → 파일로 내보내기" 버튼
  - `CompressionStream` 미지원이면 메뉴 항목 숨김
- 개인정보 안내: "링크를 받은 사람은 이 보드 내용을 볼 수 있어요. 링크 내용은 서버로 전송되지 않아요(# 뒤 부분)."

### 3-5. 공유 링크 열기 (1일)
- 시작 시(`app.js`) `location.hash`가 `#share=`면:
  1. 길이 상한 확인 → base64url 디코딩 → **압축 해제 크기 상한 1MB**(스트림으로 읽으며 넘으면 중단, 압축 폭탄 방어) → JSON
  2. 기존 `parseImport` 경로로 검증·새 ID 발급 (`assets` 없음)
  3. 확인 대화상자 "공유된 보드 ‘이름’(위젯 n개)을 추가할까요?" → 추가·전환 + 정보 알림 / 취소 → 아무것도 안 함
  4. 어느 경우든 `history.replaceState`로 `#share=…` 제거 (새로고침해도 다시 묻지 않음)
- 앱이 이미 열린 상태에서 링크를 붙여 넣어 이동(`hashchange`)해도 같은 처리
- 오류(손상·잘린 링크·더 새 버전)는 기존 가져오기 오류 문구 재사용 + "링크가 잘렸을 수 있어요"
- 오프라인(SW 캐시)에서도 동작 — 압축 해제는 브라우저 내장

## 4. E2E `tools/e2e/m5.mjs` (신규)
- 실행 취소: 위젯 추가 → 드래그 → 크기 조절 → 삭제 → Ctrl+Z 4번(차례대로 복원, 위치·크기·state 일치) → Ctrl+Shift+Z 2번
  - 이동 후 텍스트 입력 → 실행 취소 → **입력 내용은 유지**, 위치만 복원
  - 삭제 알림의 "실행 취소" 버튼, 툴바 버튼 활성/비활성, 텍스트 입력 중 Ctrl+Z는 앱이 가로채지 않음
  - 보드 삭제 → 실행 취소 → 같은 위치·위젯 복원, 다른 보드에서 실행 취소 시 해당 보드로 전환
  - 이미지 위젯 삭제 → 실행 취소 → 이미지 표시 유지
- 템플릿: 대화상자 카드 6개 → "모둠 활동" 선택 → 새 보드·위젯 4개·겹침 없음, 영어로 바꿔 만든 템플릿 문구가 영어, 빈 보드 안내 링크
- 공유: 명단 있는 보드 → 링크 생성(명단 제외 켬) → 새 프로필(다른 브라우저 컨텍스트)로 링크 열기 → 확인 → 보드 추가, 명단 비어 있음, 위치·설정 동일, 주소에서 `#share` 제거, 새로고침해도 다시 묻지 않음
  - 명단 제외 끔 → 명단 포함, 취소 → 보드 변화 없음
  - 잘린 링크·변조 링크 → 오류 알림, 압축 폭탄(작은 링크 → 1MB 초과) 거부
  - 2,000자 이하 → QR SVG 표시, 큰 그림 보드 → 32,000자 초과 안내
  - 클립보드 복사 (CDP 권한 부여 후 `navigator.clipboard.readText`로 확인)
- 오프라인: 서버 종료 후 템플릿 생성·공유 링크 열기 동작
- M1~M4 회귀
