## 1. 배경과 문제 정의

수업 중 교사는 시간 관리, 발표자 선정, 모둠 구성, 점수 기록, 활동 안내를 동시에 처리해야 합니다. 이를 위해 여러 웹사이트·앱을 오가거나, 기존 통합 도구의 저장·공유 기능에 비용을 지불해야 합니다. 또한 학교망·네트워크 불안정 환경, 학생 정보의 외부 서버 저장에 대한 우려가 있습니다.

**ClassBoardKit은 하나의 화면에 필요한 수업 도구를 배치하고, 모든 기능과 저장을 무료·로컬·오프라인으로 제공합니다.**

## 2. 목표와 비목표

### 목표
- G1. 처음 방문한 사용자가 **30초 이내** 첫 위젯을 띄워 사용할 수 있다
- G2. 보드 구성이 **자동 저장**되어 다음 접속 시 그대로 복원된다
- G3. 노트북과 태블릿(터치) 모두에서 동일하게 조작할 수 있다
- G4. 한국어·영어 사용자 모두 자연스럽게 사용할 수 있다
- G5. 1인 개발자가 유지보수 가능한 단순한 구조를 유지한다 (빌드 없음, 의존성 최소)

### 비목표 (Non-goals)
- 학생 기기 참여 기능 (원격 투표, 퀴즈 등)
- 계정, 로그인, 클라우드 동기화, 서버
- 빌드 도구, 프레임워크
- 수익화, 결제, 기능 제한
- 네이티브 앱 (PWA로 대체)
- 영상·PDF·외부 사이트 임베드 (MVP 범위 외, 추후 재검토)

## 3. 대상 사용자 (누구나, 제한 없음)

| 페르소나 | 환경 | 니즈 |
|---|---|---|
| P1. 국내 초등 담임 | 노트북 + 프로젝터/TV | 빠른 타이머, 공정한 발표자 뽑기, 모둠 점수 |
| P2. 해외 중등 교사 | iPad + 화면 미러링 | 터치 조작, 영어 UI, 수업 활동 시간 관리 |
| P3. 강사·워크숍 진행자 | 노트북 | 세션 타이머, 조 편성, 안내 문구 |

## 4. 핵심 사용 시나리오
- S1. 교사가 사이트에 접속 → 하단 독에서 타이머를 눌러 5분 설정 → 시작 (가입 없음)
- S2. 학생 명단을 붙여넣고 랜덤 뽑기 → 이미 뽑힌 학생은 제외하고 다음 학생 선택
- S3. 4개 모둠을 자동 편성한 뒤 모둠 점수판으로 수업 내내 점수 누적
- S4. "월요일 1교시" 보드를 저장해 두고 다음 주에 그대로 불러옴
- S5. 보드를 JSON 파일로 내보내 다른 기기(태블릿)에서 가져옴

## 5. 기능 요구사항

우선순위: **M**ust(MVP) / **S**hould(MVP 권장) / **C**ould(Phase 2+) — MoSCoW

### 5.1 플랫폼 기능

| ID | 기능 | 우선 | 수용 기준 |
|---|---|---|---|
| F-001 | 보드 캔버스 | M | 위젯 추가·드래그 이동·크기 조절·삭제·앞으로 가져오기. 마우스·터치 모두 동작 |
| F-002 | 위젯 독 | M | 화면 하단 독에서 클릭/탭 1회로 위젯 추가. 접기 가능 |
| F-003 | 자동 저장 | M | 변경 후 1초 이내 로컬 저장, 새로고침 시 복원 |
| F-004 | 보드 관리 | M | 보드 생성·이름 변경·전환·복제·삭제 (삭제 확인) |
| F-005 | 내보내기/가져오기 | M | 단일/전체 보드를 JSON 파일로 저장·불러오기, 스키마 검증 실패 시 안내 |
| F-006 | 배경 | M | 단색·그라데이션 프리셋 10종 이상 |
| F-007 | 사용자 이미지 배경 | C | 로컬 이미지 업로드(IndexedDB 저장) |
| F-008 | 다국어 | M | ko/en, 브라우저 언어 자동 감지, 수동 전환 |
| F-009 | 전체 화면·화면 꺼짐 방지 | S | 지원 브라우저에서 동작, 미지원 시 버튼 숨김 |
| F-010 | PWA 오프라인 | S | 최초 접속 후 네트워크 없이 전체 기능 동작, 홈 화면 설치 가능 |
| F-011 | 테마 | S | 라이트/다크 + 고대비 모드 |
| F-012 | URL 공유 | C | 보드 구성을 URL 해시로 인코딩 (명단 등 개인정보 제외 옵션) |
| F-013 | 템플릿 | C | 기본 제공 보드 템플릿 5종 이상 |
| F-014 | 실행 취소 | C | 위젯 삭제·이동 Undo/Redo |
