# ADR-0009: 실행 취소는 작업 단위 역연산 기록

- 상태: Accepted
- 날짜: 2026-11-09

## 배경
- F-014: 위젯을 실수로 지우거나 옮겼을 때 되돌릴 수 있어야 한다 (특히 태블릿 터치 실수).
- 상태는 단일 store의 불변 객체(`{ boards, settings }`)이고, 위젯은 자기 state를 수시로 바꾼다(타이머 진행, 텍스트 입력, 점수).

## 선택지
1. **작업 단위 역연산 기록** — 작업마다 `{ label, undo(state), redo(state) }`를 기록, 대상 ID로 해당 위젯·보드만 되돌림
2. 보드 전체 스냅샷 — 이전 상태 객체로 교체
3. 위젯 내부 상태까지 포함한 전체 기록

## 결정
**1. 역연산 기록** (M5 계획 D1·D2)
- 순수 모듈 `src/core/history.js`: `createHistory({ limit: 50 })` → `record / undo / redo / canUndo / canRedo / clear / peek`
- 함수는 **배열 위치가 아니라 ID로** 대상을 찾는다. 대상 보드·위젯이 없어졌으면 그 항목은 **건너뛰고(no-op) 다음 항목**으로 — 예외 없음
- 범위: 위젯 추가·삭제·이동·크기 조절, 배경 변경, 보드 삭제·이름 변경, 템플릿·공유 링크로 추가한 보드. **위젯 내부 상태(점수·명단·그림)는 제외** — 그리기는 자체 "마지막 획 취소"가 있음
- 새 작업을 기록하면 다시 실행 스택을 비움, 50개 넘으면 오래된 것부터 버림
- 같은 위젯의 연속 키보드 이동(1초 이내)은 `mergeKey`로 한 항목으로 합침
- 기록은 **세션 메모리에만** — 새로고침·언어 변경 시 사라짐. 저장 스키마 변화 없음
- UI는 "적용 + 기록"을 한 헬퍼(`ui/actions.js`의 `perform`)로만 해서 기록 누락을 막는다
- 단축키: Ctrl/⌘+Z, Ctrl+Shift+Z·Ctrl+Y·⌘⇧Z. 입력 요소·contenteditable·설정 대화상자 안에서는 브라우저 기본 동작 유지

## 결과
- 장점: "이동 → 텍스트 입력 → 실행 취소" 때 입력 내용은 유지되고 위치만 돌아감(스냅샷 방식의 데이터 유실 없음), 메모리 사용이 작음
- 단점: 작업마다 역연산을 작성해야 함, 위젯 내부 변경은 되돌릴 수 없음
- 보완: 기록 지점 목록을 TRD에 명시, 단위 테스트로 각 작업의 기록 → 취소 → 다시 실행 왕복 확인, E2E로 UI 기록 지점 확인
