## 2. 공통 규칙 (M6 전체)

- 접근성 수정은 **위젯 계약(TRD 2.2)을 바꾸지 않는다** — 필요하면 공통 헬퍼(`widgets/shared/ui.js`, `ui/dom.js`)에 넣어 위젯이 같이 쓰게
- 새 문구는 ko/en 둘 다, 앱 파일 변경 후 `tools/sw-stamp.mjs`, 상태 변경은 `actions.perform(op)` (CLAUDE.md 함정)
- 색은 토큰으로만. 새 색 조합은 대비 계산(4.5:1 글자, 3:1 경계·아이콘)을 단위 테스트로 고정
- 화면 낭독기용 문구는 짧게, 매초 바뀌는 값(시계·타이머 숫자)은 읽히지 않게 (`aria-live` 정책 표 3-3)
- E2E는 이동·새로고침 뒤 `b.ready()`, 예상된 실패 로그는 `console.info`

## 3. 작업 순서

진단 도구 → 진단 결과로 고칠 것(키보드·낭독기·색) → 새 기능(상징·꾸미기)이 처음부터 기준을 지키게 → 마무리.

### 3-1. 자동 점검 결함 수정 (2일)
- axe critical·serious를 상태별로 0으로 (D3). 흔한 유형 예상: 이름 없는 버튼(아이콘만), `aria-*` 값 오류, 대비, 중복 ID(대화상자 `share-link` 등), 목록 구조
- 접근성 트리 검사: 모든 버튼·입력에 이름, 토글은 `aria-pressed`, 팝오버는 `aria-expanded`, 위젯 프레임은 `aria-roledescription="위젯"` + 이름
- 결과를 단위 테스트로 고정할 수 있는 것은 고정 (예: 아이콘 버튼 헬퍼가 `label` 없으면 예외)

### 3-2. 키보드·포커스 (1.5일)
- **포커스 표시 통일**: 공통 `:focus-visible` 링(2px 실선 + 2px 바깥 흰/검 이중 링 → 밝은·어두운 배경·이미지 배경 모두 3:1 이상), 위젯 내부 버튼·스와치·템플릿 카드·독 항목·알림 버튼까지
- **포커스 가림 방지(2.4.11)**: 알림이 포커스된 위젯 위를 덮으면 알림 위치 조정 또는 `scroll-margin`, 툴바·독 아래로 포커스가 숨지 않게
- **탭 순서**: 보드 툴바 → 표시 설정 → 캔버스 위젯(배치 순서: 위→아래, 왼→오른, DOM 순서와 일치) → 독. "독으로 건너뛰기" 링크(포커스될 때만 보임)
- 대화상자: 닫으면 연 버튼으로 포커스 복귀(브라우저 기본 동작 확인, 안 되면 직접), 위젯 설정 패널 Esc·포커스 복귀 확인(이미 있음 → E2E로 고정)
- **단축키 도움말**: `?`(Shift+/) 또는 설정 패널 "키보드 단축키" → 대화상자(이동·크기·삭제·실행 취소·다시 실행·독 접기). 입력 중에는 동작 안 함
- 키보드로 위젯을 옮기거나 크기를 바꾸면 낭독기에 "타이머: 가로 30%, 세로 40%" 알림(3-3의 live region 사용)

### 3-3. 화면 낭독기 (1.5일)
- **알림(live region) 정책 표**를 TRD에 명시하고 맞춤:

| 사건 | 알림 | 방식 |
|---|---|---|
| 타이머 종료 | "타이머 종료" | assertive 1회 |
| 랜덤 뽑기 결과 · 주사위 결과 · 모둠 편성 완료 | 결과 문구 | polite (연출 끝난 뒤 1회) |
| 점수 변경 | "1팀 5점" | polite |
| 신호등 변경 | "빨강: 조용히" | polite |
| 위젯 추가·삭제·실행 취소 | 알림 띠 문구 | 기존 `#notices`(status) |
| 키보드 이동·크기 | 위치·크기 % | polite, 300ms 디바운스 |
| 시계·타이머·스톱워치 숫자 | 읽지 않음 | `aria-live="off"`, 요청 시(포커스) 현재 값 |

- 위젯 프레임 설명: 이름 + "Delete로 삭제, 화살표로 이동" 안내를 `aria-describedby`(한 번만 만든 숨김 문구)로
- 공용 announcer(`ui/announce.js`, 위젯은 ctx로 받지 않고 기존 `aria-live` 요소를 쓰되 규칙 통일) — **위젯 계약 변경 없음**
- 각 위젯 접근성 트리 스냅샷을 E2E로 비교 (이름·역할·값)
