# ADR-0003: 위젯 플러그인 인터페이스

- 상태: **Accepted**
- 날짜: 2026-11-04

## 배경
MVP 8종에서 시작해 15종 이상으로 위젯을 늘릴 계획이다. 위젯 추가 시 코어 코드를 수정하지 않아야 확장과 유지보수가 쉽다.

## 결정
각 위젯은 `widgets/<type>/index.js`에서 정해진 객체(type, version, createState, migrate, mount 등)를 default export 한다. 코어는 `registry.js`를 통해서만 위젯에 접근한다. 상세 계약은 [TRD 2.2](../TRD.md#22-위젯-인터페이스-계약).

## 결과
- 장점: 위젯 단위 독립 개발·테스트, 새 위젯 추가 = 디렉터리 1개 + 레지스트리 1줄
- 단점: 초기 인터페이스 설계 비용, 인터페이스 변경 시 전 위젯 수정
- 보완: M1에서 타이머·텍스트 2종으로 인터페이스를 검증한 뒤 고정

## 후속 (2026-11-04, M1)
타이머·텍스트 2종으로 검증한 뒤 인터페이스를 고정했다. M1에서 바뀐 점:
- `ctx.setState`는 병합이 아닌 **교체** (함수형 업데이트 지원) — 필드 삭제 표현을 위해
- `ctx.onDispose`, `ctx.settings` 제거 — `destroy()`와 재마운트로 충분
- `styleUrl`(선택) 추가 — 위젯 CSS를 위젯 디렉터리에 두고 부팅 시 로드
- 정의 검증(`validateWidgetDefinition`)과 버전 마이그레이션(`prepareWidget`)을 레지스트리가 담당
상세: [TRD 2.2](../TRD.md#22-위젯-인터페이스-계약)

## 후속 (2026-11-04, M2)
- 인스턴스 반환값에 선택 항목 `openSettings()` 추가 (하위 호환: 없으면 설정 버튼 미표시)
- 8종 위젯을 계약 변경 없이 추가함으로써 인터페이스 확장성 확인
