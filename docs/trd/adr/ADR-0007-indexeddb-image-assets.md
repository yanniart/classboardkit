# ADR-0007: 이미지는 IndexedDB에 저장하고 보드에는 ID만 둔다

- 상태: Accepted
- 날짜: 2026-11-05

## 배경
- M4에서 이미지 위젯(F-112)과 사용자 이미지 배경(F-007)이 생긴다.
- 보드 데이터는 localStorage(ADR-0002 로컬 전용)에 JSON으로 저장하며 브라우저 한도는 약 5MB. 이미지 한 장(수백 KB~수 MB)을 base64로 넣으면 금방 넘친다.
- 서버·계정 없음 원칙(ADR-0002)은 유지해야 한다.

## 선택지
1. **IndexedDB에 Blob으로 저장, 보드에는 이미지 ID 문자열만**
2. localStorage에 data URL — 용량 한계, 저장할 때마다 전체 직렬화
3. Cache API에 저장 — 서비스 워커 캐시와 섞이고 정리 규칙이 불명확

## 결정
**1. IndexedDB (`classboardkit` DB, `assets` 저장소)**
- 레코드: `{ id, type, blob, width, height, tone?, createdAt }`
- **ID = 내용 해시**: `a_` + SHA-256 앞 16자(16진수). 같은 이미지는 한 번만 저장 → 여러 보드가 같은 배경을 써도, 같은 파일을 여러 번 가져와도 중복 없음
- **참조 규칙** (코어가 위젯 내부를 몰라도 되도록): 이미지를 쓰는 위젯은 `state.assetId` 한 필드만 사용, 배경은 `{ type: 'image', value: assetId }`. `referencedAssetIds(boards)`가 이 규칙으로 참조를 모은다
- **정리(GC)**: 앱 시작 3초 뒤, 저장 데이터를 정상으로 읽었을 때만 참조되지 않는 이미지를 지운다. 다른 탭이 방금 넣은 이미지를 지우지 않도록 **10분 이내 생성분은 보존**. 저장 데이터 복구·임시 저장소 상태에서는 건너뜀
- **이미지 준비**: PNG·JPEG·WebP·GIF만 (SVG는 스크립트 위험으로 제외), 원본 30MB 이하. 긴 변 2048px·2MB 이하면 원본 그대로(GIF 움직임 유지), 크면 긴 변 2048px로 줄여 WebP(미지원 시 JPEG) 0.85, 그래도 2MB를 넘으면 70%씩 최대 3번 더 축소. 업로드 때 16×16 평균 밝기로 `tone`(배경 위 글자색) 계산
- **표시**: `URL.createObjectURL` 세션 캐시(`getAssetUrl`) — 같은 이미지를 위젯·배경이 함께 써도 URL 하나. GC로 지운 이미지만 해제
- **사용 불가**(사생활 보호 모드 등): 이미지 기능만 비활성 + 안내, 나머지 앱은 정상
- **백업**: 내보내기 파일에 참조된 이미지를 base64로 포함 (M4 결정 D2, data-schema §1)
- 구현: 순수 로직 `src/core/assets.js`(저장 백엔드 주입 → Node 테스트는 메모리 백엔드), 브라우저 부분 `src/ui/idb-assets.js`

## 결과
- 장점: localStorage 한도와 분리, 중복 저장 없음, 가져오기 반복에도 안전, 코어는 ID 문자열만 앎
- 단점: 저장소가 두 곳 → 브라우저 데이터 정리 시 함께 사라짐(기존과 동일한 위험), 보드만 있고 이미지가 없는 상태 가능 → "이미지를 찾을 수 없어요" 표시
- 보완: 백업 파일에 이미지 포함, 홈 화면 설치 권장(`storage.persist()`), E2E로 GC·가져오기 왕복 검증
